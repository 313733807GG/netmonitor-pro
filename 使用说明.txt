NetMonitor Pro 19 使用说明
==========================

一、直接运行

首次切换到 v19 前，建议先从托盘退出正在运行的旧版。v19 使用固定的用户级文件锁，
不论从哪个 ZIP 目录启动、是否已提升为管理员，都只保留一个正式实例；检测到旧版
窗口时也会将旧窗口唤醒而不再打开第二个。

双击 NetMonitor.exe 后，程序默认申请管理员权限；确认 Windows UAC 后会直接启用
ETW 精准进程上下行。若取消授权，程序仍会以普通权限继续启动并显示连接视图。

需要排障或明确使用普通模式时，可运行：

    NetMonitor.exe --normal-mode

普通权限下可以正常查看：

- 系统总上传/下载速度；
- 活跃进程与 TCP、UDP/QUIC 连接；
- Clash/Mihomo 等代理软件状态、接管方式、节点与分流明细；
- 代理内核 API 提供的连接上下行。

普通权限无法取得 Windows 的系统级实时进程字节事件，所以系统进程行显示“↑— ↓—”。
本版不会再用进程 OtherBytes（其中混有非网络 I/O）冒充网络速度。

二、确认或手动启用精准的各程序上下行

正常双击并确认 UAC 后会自动启用。如果此前取消了授权，也可以右键任务栏托盘中的
NetMonitor 图标，选择：

    启用精准进程流量（管理员）

确认 Windows 的管理员授权后，程序会自动重启。连接区标题出现
“Windows ETW 精准 ↑↓”即表示启用成功。

精准模式覆盖：

- TCP IPv4 / IPv6；
- UDP IPv4 / IPv6；
- 基于 UDP 的 QUIC / HTTP/3；
- 已经快速结束、来不及出现在连接表里的短连接。

三、是否需要安装驱动

不需要安装 Npcap、WinDivert 或其它第三方抓包驱动。

NetMonitor Pro 19 使用 Windows 自带的 ETW
（Microsoft-Windows-Kernel-Network）读取进程 PID、方向和字节数。
系统级 ETW 会话需要管理员权限，或账号属于 Performance Log Users 组。

四、统计口径说明

- 顶部左侧绿色一组是系统总上传/下载；右侧黄色一组是代理上传/下载，两组之间留有明显间隔。
- 顶部总网速来自 Windows 网卡累计计数。
- 系统连接区的进程 ↑↓ 来自 Windows TCP/IP 事件，按进程名聚合。
- 代理分流连接的 ↑↓ 优先来自 Mihomo/Clash 内核 API。
- rule 模式的“当前流量”来自真实连接 chains；global 模式才读取 GLOBAL 组。
- 暂时没有活跃连接时，节点显示回退到普通根 Selector 的当前选择。
- “AI节点体检”和“测AI延迟”在代理未启动、未接管或处于直连模式时仍可点击，
  但只显示自动消失的半透明状态提示，不会弹出需要手动关闭的对话框，也不会启动无效探测。
- 连接行圆点和上下行速率使用统一分类色：系统连接蓝、直连绿、代理黄、拦截红。
  名称文字保持白色。只有 Mihomo API 明确给出的最终出口才会显示绿、黄或红色。
- 连接本机代理端口只表示应用把请求交给了 Clash，不能证明最终走 DIRECT 还是付费节点。
  因此 API 未覆盖的补充行统一显示蓝色“系统连接/路径待确认”，不会再把哔哩哔哩等
  实际 DIRECT 的程序仅因连接 127.0.0.1 代理端口而误标为黄色。
- 没有内核 API、仅使用系统代理时，程序无法从进程总量中拆出真正经代理的那一部分。
  顶部黄色区会显示“≈速度 / 估算”，悬停会说明这是代理相关进程总量，不冒充精确代理流量。
- GLOBAL 明确选择 DIRECT 或 REJECT 时，AI 节点灯保持熄灭，接管灯不显示为有效代理绿灯；
  节点按钮会给出对应的透明提示，不会把直连或拦截出口当成代理节点。
- 使用本地系统代理或 TUN 时，应用与代理内核各自都有真实的本地/外部收发；
  因此把所有进程数字相加，可能高于物理网卡的实际上网流量。这不是漏算或重复事件，
  而是两个不同进程之间确实发生了转发。
- 开机自启也会申请管理员权限，Windows 可能在登录后显示一次 UAC。若要求完全静默的
  管理员自启，需要另行创建“使用最高权限运行”的计划任务。
- 自动 AI 节点探测默认每 5 分钟运行；切换“AI服务”当前节点会立即探测，手动
  “测AI延迟”会连测两次取较优值。“AI节点体检”只在点击按钮时运行。
- 自动探测、AI 节点灯、AI 节点体检和测 AI 延迟全部锁定“AI服务”策略组的当前叶子节点，
  由 Mihomo 内核直接测试 ChatGPT/OpenAI 目标，不经过订阅的“国外网站”等分流规则。
- 如果未找到“AI服务”组、内核接口不可用，或当前选择为 DIRECT/REJECT，程序会黄灯/红灯
  明示并停止；不会偷偷回退到全局、国外网站或最近活跃节点。若“AI服务”本身仍是
  url-test/fallback/load-balance 自动组，程序会锁定本次叶子节点检测，同时提示该组仍可能自动切换。
- 主窗口 AI 节点灯与横向/竖向吸附条小灯共用同一状态和悬停说明：待测黄、可用绿、
  不可用红、未接管熄灭。普通国外网站流量不会改变这三处灯的目标或颜色。

五、流量账本与超量追踪

v19 会自动建立或无损升级持久流量账本。记录来自 Clash/Mihomo 内核 API 的真实连接
累计字节差，包括：采样时间、PID、进程启动时间、程序名与路径、源 IP/端口、目标域名/
IP/端口、网络类型、进程归属来源与置信度、命中规则及内容、路由类型、策略组、真实出口
节点、完整 chains、上传/下载字节、倍率、预估计费字节和流量角色。

同一 Mihomo 连接 ID 的已知进程身份会保持稳定：优先采用 Mihomo 进程元数据，只允许
“未知 → 已知”的补全，不会因 Windows 临时端口被另一进程复用而从已知程序跳成另一个
程序。原 v17 数据库会自动升级到 schema v2，既有明细不会删除。

默认保存位置：

    %LOCALAPPDATA%\NetMonitorPro\traffic-history\traffic_history.sqlite3

保存策略：

- 分钟明细保存 30 天；
- 小时汇总保存 365 天；
- 超量事件保存 365 天；
- 同一“PID + 程序 + 目标 + 规则 + 策略组 + 节点”在一分钟内的预估计费流量达到
  100 MiB 时，会写入独立的超量事件表，并随该分钟后续流量继续更新。
- NetMonitor 自己发起的通断探测和节点体检标记为 health_check：真实字节及倍率仍保留在
  总账，便于核对订阅扣量，但默认不进入“用户程序超量事件”。

“实际流量”是该连接上传与下载字节之和。“预估计费流量”仅针对代理出口计算：

    实际流量 × 节点/策略组名称中识别出的倍率

例如“香港 3倍消耗”“倍率: 0.5”“Premium x2”会分别按 3、0.5、2 倍估算；
名称没有明确倍率时按 1 倍。DIRECT 和 REJECT 的节点计费为 0。最终订阅扣量仍应以
服务商后台为准，因为服务商可能采用额外计费口径。

右键任务栏托盘图标可使用：

    导出最近 24 小时（分钟明细）
    导出最近 1 年（小时汇总）
    打开流量账本目录

每次导出会生成一份流量 CSV 和一份超量事件 CSV，均可直接用 Excel 打开。

重要口径：只有取得 Mihomo API 的连接级字节差时才写入账本。无内核 API 时的系统连接、
TUN 网卡总量和“≈估算”不会冒充进程—域名精确历史。因此托盘显示“流量账本：运行中”
只表示数据库正常；是否产生连接明细，还取决于当前代理内核 API 是否可访问和是否接管流量。

六、故障排查

- 双击后只唤醒旧窗口：从旧版托盘选择“退出”，再启动 v19；这是跨版本防双开的保护。
- 流量 CSV 为空：确认代理已接管，并且主界面能显示 Clash/Mihomo 的分流连接，而非
  仅显示“系统连接”；首次看到某条连接时只建立累计值基线，从下一次采样开始入账。
- 托盘显示“流量账本：写入异常”：将鼠标停在该菜单项查看数据库路径和错误；确认
  %LOCALAPPDATA% 可写，然后退出并重新启动程序。
- 进程行一直显示“↑— ↓—”：请从托盘启用管理员精准模式。
- 管理员模式仍不可用：检查安全软件/系统 ETW 策略，或是否有同名 ETW 会话
  被异常残留；正常退出并重新启动通常可恢复。
- 杀毒软件提示：本版不携带 .sys 驱动。ETW 采集代码为纯 Python/Windows API 调用。
- 退出程序：右键托盘图标选择“退出”，以便立即释放 ETW 会话。

适用系统：Windows 10 / 11 x64
