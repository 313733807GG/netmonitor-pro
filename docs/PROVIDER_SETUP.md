# 代理商订阅与检测入口

IP质量检测只跟随已确认的AI真实出口，不随普通网站或其他分流节点变化。IPPure与CleanIP通过本机专用入口检测；Fl评分已在22.0.2移除，不再读取FlClash质量缓存，但FlClash代理客户端适配继续保留。

## Clash Verge Rev

将检测功能合并到全局扩展脚本，见CLASH_VERGE_SETUP.md。全局脚本正确启用时，各订阅应用时都会生成检测组和本机监听入口，通常不必按代理商逐个编写。原订阅更新链接仍须检查全局脚本保留、执行无错误；删除重导入、客户端升级或订阅自带同名组/端口时也须复核。不要覆盖已有个人规则。

## FlClash

脚本按每份订阅绑定，不因新导入另一家代理商自动继承。使用examples/flclash-ip-quality.js通用模板，在每个需要检测的订阅中启用脚本扩展并绑定。已有脚本须合并；标准附加规则和兜底设置须保留迁移，不能直接覆盖。新增订阅或删除重导入需要再次绑定；原绑定订阅内更换节点、更新节点列表通常不用重复设置。原地更新订阅链接不等于新建订阅，仍以实际绑定为准。

## 安装、AI安装和后续维护验收

1. 枚举用户打算使用的每份订阅，逐份检查绑定；无需索取或公开订阅密码、链接中的令牌。
2. 检测组应为NetMonitor-IP-Check，包含REJECT及该订阅实际节点/提供者；入口netmonitor-ip-check应仅监听127.0.0.1:17893并指向该组，UDP关闭。
3. 用户允许切换后，逐份应用订阅确认脚本无报错、实际内核组及监听存在。避免两款客户端同时争用端口，不擅自重载当前代理打断对话。
4. 代理接管启用后，NetMonitor确认AI出口，执行一次IP质量检测；核对报告出口IP，结束后专用组回到REJECT。不要批量测速所有节点来验收。
5. 普通上网/延迟正常但IP质量提示“检测入口或目标节点不可用”，优先查当前订阅脚本及节点成员，不先认定网站或节点故障。

未知名称由静态别名库维护；动态/共享IP需结合进程和历史证据，不能永久归属。配置与账本包含私人数据，不上传公开仓库。
