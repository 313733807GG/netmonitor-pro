# 使用说明：日常只需了解这些

## 1. 启动、隐藏和退出

从桌面NetMonitor快捷方式启动，按正常UAC授权启用精准流量采集。关闭窗口会隐藏到托盘；彻底退出使用托盘“退出”。首次安装不自启，之后是否手动打开由用户决定。

程序不提供代理订阅。先让自己的Clash Verge Rev或FlClash可正常使用，再查看NetMonitor状态；不要同时启动两套争用端口的代理内核。

## 2. 界面主要项目

| 区域 | 含义与操作 |
|---|---|
| 软件/接管/AI节点状态灯 | 软件运行、代理是否实际接管、AI出口检测状态；未知/异常以悬停说明为准 |
| 顶部实时网速 | 系统总体与代理相关流量，不等同于账本是否开启 |
| 当前AI节点 | 有真实连接依据的AI出口，不跟随普通视频等分流节点 |
| AI延迟 | 到探测目标的当次耗时；不代表到所有网站的网络质量 |
| IPPure/CleanIP | 第三方IP质量数据；缺失、过期、限流、验证分别说明 |
| 原生/住宅类型 | 两站证据比较，有负面证据优先保留，不因较好地址遮住风险 |
| 地区 | 有依据的层级一致性，常见地名中文化；不能可靠翻译就保留原文 |
| IP质量按钮 | 左侧主动刷新，右侧选择自动/IPv4/IPv6并复用成功资料 |
| 探测周期 | 控制AI延迟探测周期，不是流量采样或账本写入周期 |
| 连接列表 | 进程、服务、分流与实时速率；单击固定/恢复显示，不暂停后台采集 |
| 标题栏入账胶囊 | 首次显示“已暂停”；需要历史数据时用户自行点击恢复 |

连接分类通常为蓝=系统连接、绿=明确直连、黄=代理、红=拦截。颜色本身不是风险评级。仅连接本机代理端口不证明最终出口，要看实际连接链。

## 3. “进程名、目标服务名、历史入账”是不同事情

例如一条连接可显示“某浏览器 · 某视频服务”：前者依据进程信息，后者依据域名及本地名称规则。悬停可看原始名称、依据和不确定性。

实时名称识别不依赖开启流量账本。账本用于保存历史连接与流量上下文，可供以后人工或AI回看、关联和鉴定未知目标；开启它不会自动把所有未知名称识别出来。

动态/共享IP经常没有可靠归属。不要仅凭“同一IP曾和某域名出现”就永久绑定名称；未知不等于恶意，候选名称也不是已经确认的所有权结论。

## 4. 流量账本默认关闭，需要时再开启

首次安装已暂停历史入账，实时连接、已有名称识别、延迟和IP质量仍可用。无需为了使用软件先学习或打开账本。

需要回看流量、排查异常或积累未知目标鉴定证据时，可自行：

1. 点击标题栏“已暂停”，或托盘选择“恢复流量入账”。
2. 使用一段时间，之后再次点击暂停。
3. 通过托盘导出最近24小时分钟明细或更长时间的小时汇总，交给可信的维护工具分析。

开关会保存；暂停前的待写数据会刷新，暂停期间的新样本不积压、不补记，旧历史不会删除。正常入账约10秒合并写入。当前实现通常保留分钟明细30天、小时汇总365天，版本变化以Release说明为准。

计费流量按节点名中的倍率估算，实际订阅扣量以代理商为准。没有明确代理连接级证据时，不把系统网卡总量硬算成某节点的账单。

## 5. 暂停账本不等于不保存任何数据

| 数据 | 作用 | 暂停流量入账后 |
|---|---|---|
| 实时连接视图 | 当前连接、进程和分流 | 继续刷新 |
| 流量SQLite账本 | 历史流量和连接上下文 | 不记录新流量样本；旧历史保留 |
| diagnostic.log | 运行/接口/检测故障 | 仍可能记录 |
| unknown-targets.json | 待鉴定目标与必要上下文 | 仍可能更新 |
| 独立鉴定记录 | 后续复核、证据、候选状态 | 维护时按工具流程管理 |

本机数据根为`%LOCALAPPDATA%\NetMonitorPro`；窗口等设置可能在Windows注册表。数据可能包含进程、域名、节点及时间，不应把完整文件公开发到GitHub或公共聊天。需要AI协助时优先本机分析，外发前脱敏且明确范围。

## 6. IP质量能做什么、不能做什么

- 只检测已确认的AI代理出口；未接管或直连时不检测。
- 自动模式保留已观察的较差有效结果和负面证据，不保证遍历节点的所有可能出口。
- IPPure只用轻量接口，未覆盖某个IP就显示未取得；IPv6无系数不是0%纯净。
- **因CleanIP网页改版，本版本必须配置自己的CleanIP API密钥才能取得CleanIP结果，不再回退旧网页查询。** 未配置时会提示运行配置助手；IPPure、流量监控和其他功能不受影响。
- 授权API按具体IPv4/IPv6查询，发送密钥前核实专用代理链和目标节点，使用固定HTTPS端点及证书校验，不跟随重定向或回退直连。
- API摘要没有独立风险分，也没有网页全部24项核验状态；风险显示“未提供”，未返回的细项不代表通过。场景评分是API评估，不代表现场解锁测试。
- 授权或配额错误（如401、403、429）停止本轮后续API查询，不自动反复请求；已有成功缓存与失败状态分别保留。
- 不后台拉起浏览器、不绕过网站验证、不另做DNS/WebRTC泄漏测试，不批量测试代理商节点。
- 不同时间同一IP分数变化可能来自网站数据更新，比较时要同时核对IP、协议和时间。低ChatGPT延迟不保证该站访问成功。

### 必需：申请并配置CleanIP API密钥

只有CleanIP质量查询需要密钥，NetMonitor本身及其他监控功能不要求密钥。

1. 访问[CleanIP官网](https://cleanip.io/)，按改版后的当前页面指引领取或创建自己的API密钥；具体入口、额度和规则以官网为准。
2. 下载并解压本Release的**源码ZIP**，在其根目录用独立Python 3.12运行：

```powershell
py -3.12 -I tools/configure_cleanip.py
```

3. 在隐藏输入提示中粘贴自己的密钥，输入时屏幕不会显示明文。配置后重启NetMonitor或手动刷新IP质量。

不要把密钥粘贴到命令行参数、脚本、Issue或聊天中，也不要把密钥发给安装AI。密钥只以当前Windows用户的DPAPI加密保存于`%LOCALAPPDATA%\NetMonitorPro\credentials\cleanip.dpapi`，不能跨Windows用户直接复制；更换Windows用户后需重新配置。仓库、源码ZIP和程序ZIP均不包含任何用户的真实密钥。普通EXE运行不需要Python，只有配置或更换密钥的助手需要Python 3.12和源码ZIP。

## 7. 什么时候找AI维护

经常未知的服务名、客户端升级后接口失效、订阅新增后评分入口缺失、持续错误或账本异常时，使用[维护说明](MAINTENANCE.md)。不需要日常反复切换开关或批量测速。
