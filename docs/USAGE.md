# 使用与维护

> v22.0.1 最新行为与维护变化见 [V22_CHANGES.md](V22_CHANGES.md)；FlClash 配置见 [FLCLASH_SETUP.md](FLCLASH_SETUP.md)。

首次使用先看[详细安装](INSTALLATION.md)；需要更新别名、修复接口或处理数据问题时看[后期维护](MAINTENANCE.md)。[AI安装入口](AI_INSTALL.md)会要求助手阅读这套完整文档。

## 日常操作

1. 启动Clash Verge和NetMonitor，查看顶部“软件 / 接管 / AI节点”灯。软件灯表示客户端界面进程；关窗后后台内核可能继续运行。接管灯反映系统代理/TUN接管及当前状态，不表示每条连接都走代理。AI节点灯反映探测/等待状态，悬停看依据，不等于账号服务可用。
2. 上方四个速率、折线与下方连接列表有不同统计口径。先查看系统代理、TUN、严格路由和模式，再结合连接行的出口判断当前流量；不要只按节点行推断全机出口。
3. 悬停连接行查看原始目标、进程、命名依据、规则和实际出口。点击连接区可固定/恢复列表，固定只停止行刷新，不停止采集；标题会显示固定提示。切换系统/代理列表时会解除固定。
4. 拖动窗口到屏幕边缘可吸附为迷你条，悬停展开；界面钉住/固定状态与连接列表固定是两回事。展开面板上显示当前节点、评分、风险标记、地区和两种IP类型标签，长文字悬停看完整信息。
5. 用“探测周期”选择AI延迟探测间隔；“测AI延迟”手动检测HTTP耗时；“IP质量”手动刷新两站结果。检测时对应按钮显示检测中并暂时禁用，线程结束恢复；不要把两个检测按钮的结果混为同一种延迟/风险指标。
6. 右键系统托盘图标，可显示/隐藏窗口、启用管理员精准流量、查看待鉴定三类计数、打开诊断/账本目录、导出流量、选择开机自启及退出。开机自启是可选功能，安装并不要求启用。需要真正退出时选择托盘“退出”，隐藏窗口不等于停止程序。

托盘可导出“最近24小时（分钟明细）”或“最近1年（小时汇总）”。导出在后台执行，以完成提示为准；软件没有记录的时段不会补造。CSV及异常摘要可能含节点/域名等信息，分享前脱敏。导出用于阅读统计，不代替SQLite与设置的完整备份。

## 适配范围

本版已在 Clash Verge Rev 和 FlClash 0.9.2 实机验证，其他 Mihomo 内核客户端可能适用但不保证。非 Mihomo 内核不建议下载使用。NetMonitor 不提供代理服务，浏览器仍遵循其正常分流规则。

## 流量、节点与延迟

绿色是系统/直连相关数据，黄色是代理相关数据；蓝色用于归属未确认，红色用于阻断/失败等状态，需结合行内文字及悬停依据。不能把系统所有网卡字节与代理节点用量直接等同；网卡、ETW、内核连接统计是不同口径，转发、连接生命周期及采样都会造成差异。账本/倍率估算不等于代理商最终账单。

规则模式可同时存在多个出口。AI 节点优先采用已观测的 ChatGPT/OpenAI 连接，其次 Claude/Gemini；全局模式采用 GLOBAL 的真实叶子节点，直连/不明确状态不猜测。切换其他分流出口不会直接刷新 AI 节点结果；没有可信目标时等待确认。严格路由是从内核读取的配置状态，不是对整个本地网络可达性的测试；TUN 关闭时显示未生效状态。

“探测周期”只控制 AI HTTP 延迟检测，“测AI延迟”可手动检测。耗时测量使用 ChatGPT HTTP 测试 URL，不检测账号登录、地区解锁、模型调用或完整服务。HTTP 403/验证页不必然代表节点断网。

“IP质量”需要[专用检测入口](CLASH_VERGE_SETUP.md)。本次进程按订阅标识+节点名缓存，包括失败结果；切回已检测节点直接显示缓存。更换其他分流组不重复检测，手动按钮可以刷新。不开系统代理/TUN、AI 直连或控制接口失效时不检测。节点出口漂移但名称不变时需手动刷新。关闭软件后缓存清除。

## 检测结果如何展示

- IPPure 为其风险系数，数值低通常更纯净；CleanIP 纯净度高通常更好，风险分低通常更好。不要把三者当作同一指标。
- 原生/广播、住宅/非住宅是两个维度。非住宅不必然等于机房；保留网站实际分类，不能从分数反推类型。
- 住宅维度可加入FlClash同IP有效缓存；原生/广播仍由两站判断。一致采用CleanIP样式，分歧优先明确非住宅/非原生证据；多个负面来源按CleanIP→IPPure→FlClash。无缓存不宣称三方通过，不同IP不合并。详见[FlClash说明](FLCLASH_SETUP.md)。
- 地区尽量显示“地区 · 城市”等两级名称，去外围国家前缀，保留台湾/香港等地区标识；一致采用 CleanIP，地址冲突显示 CleanIP 并注明分歧，不补造网站未返回的区县。
- 风险标记很长时与地区分别省略，悬停查看完整信息。未检出不等于无风险；地理库可能过期、不同语言也可能产生分歧。

## 未知名称维护

数据默认在 `%LOCALAPPDATA%\NetMonitorPro`：

| 数据 | 位置/用途 |
|---|---|
| 诊断日志 | `logs/diagnostic.log`，轮转保存启动、接口及检测异常 |
| 待鉴定清单 | `logs/unknown-targets.json`，本地 JSON 数组 |
| 流量账本 | `traffic-history/traffic_history.sqlite3`，可能伴随 WAL/SHM |
| 窗口等设置 | Windows QSettings，`HKCU\Software\NetMonitorPro` |

待鉴定项按 `review_category` 分为 `domain` 500 条、`ip` 500 条、`anomaly` 200 条；分别淘汰本类最久未见项目。裸 IP 并非都能确认是动态 IP。记录有首末时间、轮询观测计数、进程/路径/规则/出口等上下文，每目标最多 16 组上下文。计数不是连接次数或网页访问次数。旧版已淘汰记录无法恢复，软件关闭时段的连接也无法补抓。

每约 60 秒节流写盘、退出时强制尝试保存；原子替换失败保留待写状态，写诊断日志并重试。硬盘故障、权限或非正常断电仍可能影响保存，不承诺永久历史。

建议流程：

1. 正常使用几天，在托盘查看三类数量与日志目录。先复制必要记录并脱敏，避免把整份日志上传公开渠道。
2. 结合来源程序、父进程、原始域名、连接规则及官方资料核实。CDN、共享 IP、随机域、模拟器流量不能仅凭外观归因；证据不足继续保留未知。
3. 修改 `src/connection_labels.py` 中对应友好名/域名/品牌匹配表，保持域名边界，避免一个 CDN 后缀误伤全部租户；异常文字证据独立保留。
4. 运行测试并重新构建，退出旧实例后替换完整发行目录。新版加载别名后会清理已确认的服务待鉴定项，独立文本异常不应因服务别名而丢失。

修改 JSON 的显示名不会自动成为识别规则；便携包中的识别代码是冻结的。公开 Issue 可只提供脱敏域名、版本、错误摘要及复现步骤。静态库中的归属也可能过期，需要持续维护。

## 升级与故障

升级前退出 NetMonitor，保留完整旧安装并备份用户数据和 QSettings。SQLite 正在写入时不要只复制主文件，使用一致性备份或退出后备份整个数据目录。切勿用空白示例数据覆盖自己的账本。源码目录、安装目录与用户数据是独立位置。

运行失败先看诊断日志或启动弹窗。Windows 智能应用控制可能阻止未签名 EXE 或某个依赖 DLL，应检查 Windows 安全记录；请勿关闭系统保护、复制来源不明 DLL 或反复打包换哈希。源码运行同样取决于本机 Python、SSL/Qt 依赖的可信状态。

精准流量依赖 ETW 权限；普通权限降级不等于全部计数可信。连接名可能只有进程、裸 IP 或未知，不代表恶意程序。控制 API 不可达时不能可靠推断代理出口，不应把未知解释为直连。

Clash Verge 更新、订阅重载或脚本替换后，复核专用组/监听器是否仍存在；重新应用配置可能中断网络，选好时机。不要同时让两个代理软件争用相同监听端口，亦不要同时运行源码版与 EXE 采集同一个 ETW 会话。
