# 给AI的自动下载安装与配置任务

本指南针对本仓库已发布、经manifest声明并验证默认设置的正式版本。执行模型需要Windows本机文件/终端权限及网络访问能力。没有这些能力时明确说明边界，提供可执行步骤，不假装已经安装。

## 一、任务目标与默认决定

完成“下载并校验→完整安装→默认设置→代理软件关联→实际验收→简短说明与本机维护记录”。不能只把ZIP下载完就交回给用户。

安装授权包括必要的本软件文件与设置、Clash Verge全局检测脚本合并或FlClash逐订阅绑定。可确定的可逆步骤直接完成。仅在无法自动确定安全目标、两款客户端都在接管、没有可用非系统盘、已有扩展无法可靠保留，或需要用户登录/UAC/安排断网重载时请求必要配合。

**默认不询问的项目：**

- 非系统盘安装；不自动分区、不改变盘符。
- NetMonitor自启动关闭；不问“是否开启”，不创建计划任务。
- 首次历史流量入账关闭；不问“是否开启”。升级保留用户明确保存过的入账选择。
- 保持现有代理模式、普通节点、DNS/TUN及个人规则；不用替换整份配置来省事。
- 不安装Python、Node、Edge/Chrome驱动来运行便携程序，不恢复后台浏览器检测。

先阅读同一Release的[安装说明](INSTALLATION.md)、[代理配置](PROXY_SETUP.md)、[使用说明](USAGE.md)、[维护说明](MAINTENANCE.md)以及两个examples脚本。仓库main可能领先Release，不混用版本。

## 二、盘点：只读取任务需要的内容

1. 检查Windows x64、当前实际用户与权限；提升权限使用正常UAC，不索取用户密码或替用户确认系统提示。
2. 查已有NetMonitor实例、快捷方式、安装目录和文件版本；窗口隐藏不等于退出。存在源码版时也检查，禁止两套采集并跑。
3. 确定系统盘（读取SystemDrive及Windows所在卷，不能硬认C盘）；枚举已挂载、解锁、可写的本地固定磁盘。排除系统卷、恢复卷、光驱、网络盘、可移动介质和重解析路径。用一个可回收的临时文件验证目标目录可写。
4. 优先沿用已有非系统盘安装；否则优先合适的D盘，再按确定顺序选择其他非系统固定盘，目标为`<盘符>:\Apps\NetMonitor`。至少预留解压包、暂存、旧安装备份所需空间并留余量。报告选择结果，不为每个正常磁盘选择重复询问。
5. 若只存在系统盘或旧安装在系统盘且没有合适迁移位置，暂停安装路径相关步骤，只询问一次可用位置。不能默认退回`%LOCALAPPDATA%\Programs`或桌面。
6. 识别已有Clash Verge Rev/FlClash、当前运行客户端、内核版本和订阅扩展。不要要求用户把完整配置、订阅链接或密钥贴进聊天。两款都安装不等于两款要同时运行。
7. 检查普通代理端口、控制接口及`127.0.0.1:17893`的占用者。不要结束不明进程。

本机候选路径来自[代理配置](PROXY_SETUP.md)，只是探测线索；便携版或新版路径可能不同，必须核对实际进程/客户端设置。

## 三、确定版本、下载并校验

若用户指定版本，锁定该tag；否则查询仓库最新正式Release，排除draft/prerelease，再固定本次tag及commit。示例只读取公开元数据，不需要把GitHub账号令牌发给用户：

```powershell
$repo = '313733807GG/netmonitor-pro'
$release = Invoke-RestMethod -Uri "https://api.github.com/repos/$repo/releases/latest" -Headers @{Accept='application/vnd.github+json'}
if ($release.draft -or $release.prerelease) { throw '不是正式版本' }
$releaseTag = [string]$release.tag_name
# 使用该Release返回的资产信息，不根据网页广告或第三方搜索结果猜下载地址。
```

下载同一Release的Windows x64 ZIP、`release-manifest.json`和`SHA256SUMS.txt`到独立暂存目录。选择资产必须唯一，失败页面/零字节/重复同名项都不是有效下载。根据SHA256SUMS分别校验ZIP及manifest；如API提供资产digest，再交叉核对。哈希一致只证明一致性，不代替发布者签名。

manifest必须与tag、Windows文件版本及包中EXE一致，并声明本版首次入账关闭、自启动关闭、无后台浏览器。若最新Release仍缺少这些要求或是旧行为，报告具体差异，不默默安装旧版后宣布符合要求，也不擅自在用户电脑现场改源码重打包。

拒绝`template_only=true`、仍有占位符或`validation.first_run_defaults_tested`不是true的模板/未验收清单。Windows x64发行包不等同于ARM64或32位原生支持；架构不匹配时不要静默尝试。

校验行读取示例：

```powershell
$pattern = '^([A-Fa-f0-9]{64})\s+\*?' + [regex]::Escape($packageName) + '$'
$rows = @(Get-Content -LiteralPath $checksumFile | Where-Object { $_ -match $pattern })
if ($rows.Count -ne 1) { throw '没有唯一匹配的SHA256记录' }
$expectedHash = [regex]::Match($rows[0],$pattern).Groups[1].Value
$actualHash = (Get-FileHash -LiteralPath $packagePath -Algorithm SHA256).Hash
if ($actualHash -ne $expectedHash) { throw '下载校验失败' }
```

先检查ZIP条目：拒绝绝对路径、`..`路径穿越、重解析/符号链接及越出解压根目录的条目；检查解压后所需空间。完整解压到新暂存目录，再定位包含EXE与`_internal`的根目录，不能只取EXE或直接从ZIP启动。

## 四、先设置默认值，再第一次启动

已有实例时协调用户从托盘退出，再核对进程。备份完整旧安装、原数据及注册表设置；SQLite运行时用一致性备份，退出后复制完整目录并包含WAL/SHM，不只复制主库。

将完整发行目录放入选定非系统盘目录。不要把新目录嵌套进旧目录或混用旧DLL。创建桌面“NetMonitor”快捷方式，工作目录指向实际安装目录。

**首次启动前**设置当前实际用户的`history_paused=true`，关闭本软件自启，详见[安装说明](INSTALLATION.md)。可用随包`tools/Initialize-NetMonitorDefaults.ps1`辅助；先审阅并确认身份/安装路径。首次安装用其默认模式；有明确旧入账选择的升级才传`-PreserveExistingHistory`。不得在运行中的程序旁修改设置，让退出时旧值覆盖新值。

检查HKCU Run、启动文件夹、HKLM Run和计划任务中是否有明确归属NetMonitor的历史入口。标准助手只处理当前软件使用的HKCU项；其他入口由AI核对目标后单独关闭，无法确认归属就报告冲突，不删除无关对象。不要改代理软件的自启。

首次关闭账本不删除旧数据库，不代表隐藏实时连接。测试应使用隔离数据与隔离QSettings，不能为了验证写入而暂时给用户真实账本开启入账。

## 五、完成两款代理软件关联

按[PROXY_SETUP.md](PROXY_SETUP.md)执行，而不是只把脚本发给用户：

- **Clash Verge Rev**：发现并保留既有全局扩展，合并函数及唯一main调用，验证每次订阅应用都会生成专用组/监听器。
- **FlClash**：确认本机控制接口启用且认证有效，枚举现有订阅，保留standard/script扩展中的原规则与兜底，再合并并逐订阅绑定。
- 当前已有可用客户端时优先使用它；不要为“支持两款”擅自安装或启动第二套。两款都需配置时可分别准备持久配置，实际运行验收按用户允许的时机逐款进行。
- 没有这两款客户端或没有用户自己的有效订阅时，先明确前置缺失。NetMonitor不附带代理，不能凭空生成订阅；未经请求不替用户安装其他代理软件。

先备份、离线验证合并结果；将需要重载的修改集中一次，说明可能短暂断网并确定用户可接受时机。确认后再应用。禁止重写正在打开的FlClash数据库、覆盖订阅配置或批量测速全部节点。

## 六、验收顺序与成功标准

1. 启动正式EXE并完成正常UAC；确认只有一个实例且路径正确。Windows拦截时记录具体EXE/DLL与错误，不关闭保护、不换无关DLL或反复改哈希求放行。
2. 实时连接正常，ETW或普通模式状态如实显示，当前代理接口可用。
3. 新安装标题栏显示“已暂停”，托盘提供“恢复流量入账”。观察至少两个10秒写入周期，在有真实实时流量时账本**没有新增样本/流量值**；已有库仍可读。允许SQLite建表、元数据或WAL发生文件层面变化，不用文件大小不变代替数据验证。
4. 核对本软件自启动项为空/关闭；不询问是否要打开。
5. 验证当前客户端的控制接口、专用监听、真实AI出口与一次IP质量检测；网站失败单独记录，不把它写成安装失败或检测成功。完成/取消后组应回到REJECT，普通组保持原选择。
6. FlClash所有目标订阅的持久绑定必须核对；未实际切换验证的订阅明确标“绑定已检查，运行未验收”，不能宣称全部实测。
7. 没有新增检测浏览器进程、自启或计划任务。完成后删除无用下载暂存，不删除升级备份与用户数据。

无网络、无代理接管或没有可核实AI出口时，不为满足清单强行改用户网络。清楚列出“软件已安装/关联配置已准备/哪些实机项目尚未验证”。

## 七、向用户交付：一次简短说明即可

报告实际安装路径、版本、校验通过、当前关联客户端、必要配置状态、自启动关闭、入账状态及备份位置。附本机维护记录路径和使用文档链接。

首次安装直接说明：

> 历史流量入账默认关闭，不影响实时连接或已有名称显示。账本可在需要时保存历史上下文，帮助你或AI回看流量和鉴定未知目标；不会自动识别所有未知名称。你以后可点击“已暂停”或托盘“恢复流量入账”自行开启，暂停期间不会补记。关闭入账后诊断和待鉴定日志仍可能保存在本机。

不要再追问是否开启入账或自启，不做未请求的性能/网络大改，不建立持续自动维护任务。

API依据：[GitHub Release API](https://docs.github.com/en/rest/releases/releases)。设置依据：[Qt QSettings](https://doc.qt.io/qt-6/qsettings.html)；实际键名以该Release源码为准。
