# 后期使用与AI维护

## 1. 安装AI应留下的本机记录

记录：安装路径、版本/tag/commit、EXE和ZIP哈希、来源Release、当前客户端及版本、控制接口类型（不含密钥）、专用组/端口、各订阅绑定状态、未验收项目、入账与自启状态、备份路径、数据/设置位置。

记录仅存本机；不保存订阅令牌、明文控制密钥或全部配置。让用户只需把记录路径和本页交给下一个AI，不必重新解释所有背景。

## 2. 给后续AI的任务模板

> 请先读取本机NetMonitor维护记录和对应版本的docs。保持非系统盘安装、NetMonitor自启动关闭，不主动询问是否开启；尊重我已经选择的入账状态。先只读检查，再完成本次问题所必需的修复和验证。保留原始流量事实、日志及用户规则，不恢复已取消的后台浏览器，不批量测速，不索取完整订阅密钥。可能断网、需退出软件或需要UAC时提前说明。最后更新本机记录，清楚区分已修复、外部限制与未验证项目。

## 3. 未知连接名称如何维护

1. 先看连接行悬停中的进程路径、原始域名、分流和证据，不仅看显示名称。
2. 本机查看待鉴定日志，必要时结合**已经存在**的历史账本。没有历史也能按现有证据分析，不为了安装/普通识别强制开启入账。
3. 如确实需要观察新的历史上下文，解释目的和隐私影响，由用户自行决定是否开启，观察结束后可再暂停。
4. 用官方域名/文档、程序路径、重复观测等交叉核验；弱关联保留候选，不把动态共享IP写成永久归属。
5. 确认后更新合法的名称规则及测试，再构建匹配版本；不要直接改原流量记录来让界面看起来“已识别”。本地鉴定结果与公开通用规则分开，公开前脱敏。

## 4. 常见问题

| 现象 | 首先检查 | 不应做什么 |
|---|---|---|
| 节点长时间待确认 | 系统代理/TUN实际运行、普通入口、真实AI连接链、候选/重试日志 | 用所选名称冒充真实出口，或全节点测速 |
| 评分入口不可用 | 当前订阅脚本、组成员、监听及端口冲突 | 改系统代理为17893，覆盖整份订阅 |
| 切订阅后评分失效 | FlClash新订阅绑定、Verge全局脚本执行 | 假定所有订阅自动继承 |
| CleanIP提示未配置密钥 | 网页已改版，本版本不再回退旧网页；由用户按官网指引领取密钥并用配置助手隐藏输入 | 索取用户密钥、恢复旧网页查询或把未配置当作纯净 |
| CleanIP未就绪/超时/401/403/429 | 区分授权API、真实IP、当前线路、密钥权限和每日额度 | 缺失当纯净，关闭证书验证、绕过验证或自动反复请求 |
| CleanIP密钥读取失败 | 是否在原Windows用户下配置、DPAPI文件是否损坏；必要时用隐藏输入重新配置 | 把密钥贴进聊天/命令行，或跨用户复制加密文件 |
| IPPure缺另一协议资料 | 轻量接口只返回当前实际出口，明确未取得 | 重新加后台Edge自动补查或冒用其他IP分数 |
| 界面像重启 | 进程创建时间、启动日志与控制接口重连记录 | 没证据就认定进程崩溃或重载 |
| 入账已暂停但文件变化 | 区分流量样本、数据库元数据和独立日志 | 把所有写盘都说成流量入账仍开启 |
| Windows阻止启动 | 被阻止的具体EXE/DLL、CodeIntegrity记录、来源完整性 | 关闭安全保护、随意换DLL、换哈希碰运气 |
| 暂停后历史看不到新增 | 本来就是预期行为，核对开关与时间范围 | 自动恢复入账或重建数据库 |

## 5. 更新代理软件或订阅

先保存必要设置，更新后重新核对控制接口/认证、实际监听器和脚本生成结果。FlClash新增/删除重导入的订阅需要重查绑定；原地更新也要核对原绑定仍在。升级客户端不等于授权修改普通规则或所有节点选择。

不得写死旧客户端版本的数据库字段、脚本ID或界面坐标。查当前版本支持方式，无法可靠保留旧扩展时报告限制，不以“能启动”为由宣称关联配置完成。

## 6. 数据与回退

程序安装目录、用户数据和设置是不同位置。备份SQLite需保持一致性；已退出时复制完整目录，运行中用SQLite备份机制。回退程序不默认覆盖历史数据库，卸载也默认保留历史。

无浏览器版不会再生成检测用Edge会话。若升级前有旧版本专属会话残留，只按精确临时资料目录核实，不按所有msedge.exe批量结束。必要时让用户择时正常注销/重启，确认无活跃使用后再清理专属目录，个人Edge资料不在范围内。

完成后更新版本、变更、验证证据、回退点及未解决事项。无需重复测试已通过且未受改动影响的所有历史场景，不自动安排长期后台任务。
