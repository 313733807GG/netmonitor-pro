# 详细后期维护与AI维护指引

> v22.0.1 最新行为与维护变化见 [V22_CHANGES.md](V22_CHANGES.md)；FlClash 配置见 [FLCLASH_SETUP.md](FLCLASH_SETUP.md)。

本页供使用者及具有本机权限的AI助手参考。仅Clash Verge Rev实机适配，其他Mihomo客户端需要自行核验；非Mihomo内核不建议使用。维护不意味着可以自动修改代理规则、关闭安全保护或公开个人数据。

## 维护频率与记录

正常运行不需要每天手工清理。可使用数天至一周后查看待鉴定数量、诊断日志和账本状态；Clash Verge升级、订阅/节点变化、检测网站报错或应用升级后额外检查。这里是人工建议，不会自动创建后台任务或上传日志。

维护前记录NetMonitor/Clash Verge/Mihomo版本、实际EXE路径、源码位置、数据路径和症状时间。保存必要的脱敏样本、归属证据、改动文件、测试结果及回退位置，写到自己的本地维护备忘。不要把维护者电脑路径当作他人的固定安装路径。

| 事项 | 常规检查 | 需要维护时 |
|---|---|---|
| 未知名称 | 托盘三类计数，unknown-targets.json最近样本 | 核实静态别名、重新测试构建 |
| 日志写入 | 是否新增错误、保存失败或时间停滞 | 排查磁盘、权限、文件锁，核实重试 |
| 流量账本 | 托盘状态、旧记录和新记录连续性 | 一致性备份、只读检查、定位路径/写入问题 |
| 代理接口 | 模式/TUN/连接/出口是否有可信数据 | 重新核对客户端版本与本地控制通道 |
| IP评分 | 节点缓存、检测错误与两站IP是否一致 | 手动刷新一次，必要时适配解析器 |
| 专用入口 | Verge升级后组/监听器/节点集合仍在 | 合并修复脚本，择时应用，不覆盖个人规则 |

## 未知名称：从留证到生效

1. 读取`%LOCALAPPDATA%\NetMonitorPro\logs\unknown-targets.json`。分别统计`review_category=domain/ip/anomaly`；额度是500/500/200，不是一个总500。不要通过删裸IP来让域名“有名额”。
2. 选取域名/其他名称或异常文本的少量代表样本，保留必要的目标、首末时间、上下文来源程序/父进程/路径、规则与出口依据。观测计数不等于连接数。记录可能在60秒节流周期后才写盘，不要立即判定漏记。
3. 优先用官方域名列表、应用官方资料或本机可信应用证据核实。裸IP、CDN、PCDN、模拟器内流量和随机域不能只凭相似名字猜归属；WHOIS或共享服务器只能作线索，不足以证明具体应用。
4. 有证据时修改`src/connection_labels.py`：`ALIASES`用于域名服务名，`PROC_FRIENDLY`用于进程友好名，品牌/父进程表用于已有归属机制。阅读现有匹配逻辑，把更具体规则放在通用规则之前，避免共享CDN后缀匹配所有租户。
5. 为新增规则检查正例与反例。例如匹配`service.example.com`时，不应误匹配`fake-service.example.com.invalid`；共享托管根域不能直接全部归给某个客户。不要修改真实JSON试图永久改名，也不要让已知服务别名清掉独立乱码证据。
6. 运行源码测试，通过后构建。EXE中的识别库是冻结的，仅修改.py文件不会改变正在运行的EXE。按[升级步骤](INSTALLATION.md#6-升级与回退)退出旧实例、备份并替换完整发行目录；源码版也应重启加载改动。
7. 启动后确认显示名与依据正确、已确认服务待鉴定项被清理、乱码异常仍保留、原计数/上下文迁移正常。无证据目标继续未知，不为减少数量而伪造标注。

不要删除已淘汰记录后再声称“恢复了历史”。日志未记录的过去、旧配额已淘汰的内容及软件未运行时流量无法自动补回。

## IP质量与节点问题

按顺序区分：是否有系统代理/TUN接管 → 是否为代理而非直连 → 控制API是否可用 → AI真实叶子是否已确认 → 专用组是否包含该节点 → 本机17893是否由正确监听器占用 → 两站是否实际返回合法数据。

同名节点出口漂移、服务商更新同名节点或先前请求失败后，缓存仍可能保留。先手动点击“IP质量”刷新一次，避免连续自动重试。其他分流组变化不要求跟随切换AI展示目标；浏览器的检测网页也可能按普通规则走另一个出口。

出现HTTP限流、人机验证、HTML代替JSON、字段缺失或CleanIP文本格式变化时，保留明确错误，不把节点直接判坏。对照`src/ip_quality.py`中的`parse_ippure`、`parse_cleanip`和来源融合逻辑，使用脱敏/合成响应样本测试后再适配。不得绕过验证码、伪造风险分或在失败时静默改用直连。

两站IP不同不能合并类型/地区；只有一站返回时说明单来源。类型两维度独立，负面证据优先及一致时CleanIP样式的约定不能因新接口而丢失。地区数据库冲突保留说明，不补造更细城市/区县。

检测结束后专用组应恢复REJECT。程序被强制终止、崩溃或控制接口断开时，finally恢复操作不保证成功。此时检查并仅把`NetMonitor-IP-Check`改回REJECT；不要改普通选择组。若无法确认原因，暂停检测并保留脱敏错误摘要。

## Clash Verge或内核升级后

先确认客户端自身网络正常。核对控制器命名管道/本机API、认证读取权限及Mihomo版本，再看NetMonitor状态；不得把控制接口密钥输出到公开日志或把API开放到公网。

检查有效配置中专用组名称、类型、REJECT默认项、当前订阅节点集合与`127.0.0.1:17893`监听器。全局脚本更新可能覆盖示例，订阅也可能改变节点集合；与原脚本比较后合并，不能覆盖用户新增规则。需要重载时先告知断网影响并等待合适时机。

严格路由是配置读取结果；v1.19.32可能省略false字段，当前代码只对完整可信结构采用false默认。新内核返回结构变化时应检查`monitoring_state.py`和`controller_transport.py`，不能把所有缺失/异常都当“关”。其他Mihomo客户端的路径/通道/认证兼容应单独验证，不能据此宣称正式适配。

## 日志、账本与备份

- `diagnostic.log`约2MiB轮转、最多3份备份，旧错误可能被正常轮转淘汰；需要调查的少量记录先复制到私有位置。
- `unknown-targets.json`采用原子替换，约60秒节流写盘，失败保留dirty并记录warning重试；退出也会尝试保存。看到保存失败先检查路径、剩余空间、写权限及文件锁，等待后续重试并核对时间/内容，不直接清空日志。
- 账本目录为`traffic-history`，数据库可能伴随WAL/SHM。退出软件后完整备份，或由熟悉SQLite的助手用一致性备份接口；导出CSV便于阅读，但不能替代原库及设置备份。
- 窗口位置等QSettings位于`HKCU\Software\NetMonitorPro`。备份数据目录不等于已备份注册表。恢复需确认机器/账号与目标，避免覆盖新记录。
- 软件可能读取`NETMONITOR_LOG_DIR`、`NETMONITOR_HISTORY_DIR`、`NETMONITOR_LOCK_DIR`测试覆盖。维护自检使用隔离目录，正式启动确认没有残留覆盖，不能把测试数据当真实历史。

账本疑似损坏时先停止写入并保留完整副本，再在副本上检查。不要直接删除WAL/数据库、重建空账本或恢复旧库覆盖持续增长的数据来消除错误提示。

## 排障速查

| 现象 | 优先检查 | 不应采取的动作 |
|---|---|---|
| 点开没有新窗口 | 是否已有实例、托盘是否隐藏、实际快捷方式路径 | 连续启动多份、手工删锁掩盖问题 |
| 精准流量不可用 | UAC/管理员、ETW状态及日志 | 把估算当精准，强行停止无关ETW会话 |
| 软件灯灭但仍有代理流量 | Verge窗口关闭但后台内核仍运行 | 仅凭软件灯推断代理已断开 |
| 接管灯亮但某连接直连 | 规则/全局选择、实际连接出口 | 假定TUN让所有流量都走代理 |
| AI等待、严格路由未知 | 可信连接证据、API及返回字段 | 无证据填节点或将未知写成关 |
| IP入口不可用 | 专用组/监听器、节点集合与端口冲突 | 改浏览器代理为17893或静默使用普通出口 |
| 分数不变 | 本次缓存键和动态出口是否变化 | 反复切换无关分流组触发重测 |
| 界面连接不刷新 | 是否单击连接区固定了列表 | 立即判定采集线程卡死 |
| 启动报SSL/DLL被阻止 | 具体文件、应用控制事件、受信任构建环境 | 关闭安全保护或下载来源不明DLL |
| 历史似乎“丢了” | 实际数据路径、账号、测试环境变量、旧快捷方式 | 未查路径就新建/覆盖数据库 |

## 源码改动与发布验收

使用自己的Windows Python3.12环境，源码根目录运行README中的check/test/build。192项是本版基线，后续用例数量可变化。测试不应与正在运行的EXE并行启动同名ETW采集；自检需要隔离日志、账本及锁。

关键文件：`connection_labels.py`管名称；`unknown_log.py`管待鉴定持久化；`controller_transport.py`/`pipe_client.py`管控制接口；`ip_quality.py`管出口证据/取分/缓存；`monitoring_state.py`管状态判定；`traffic_capture.py`管ETW；`traffic_history.py`管账本；`app.py`/`status_ui.py`/`ui_theme.py`管界面交互。

业务修复通过适当回归后再构建、升级验收，确认原账本继续写入、普通组未变、专用组恢复REJECT；维护备忘记录版本、证据、测试和回退。公开发布时同步源码、版本、展示图、文档、许可、Release附件及校验值，先检查图片/日志隐私。
